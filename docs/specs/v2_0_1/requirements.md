# OCPP 2.0.1 — Requirements

Messages, datatypes and enumerations for OCPP 2.0.1, generated from the official Open Charge Alliance JSON schemas.

Normative. IDs are stable and append-only (OB-R-nnn) — never
renumber, never reuse a retired ID. Boundary behavior and stated limitations live
in [`edge-cases.md`](./edge-cases.md).

Requirements are added through the workflow in [`AGENTS.md`](../../../AGENTS.md):
gate 1 approves the "shall" text before any code is written. This file is
deliberately empty until then — an unapproved requirement here would be a
specification nobody agreed to.
